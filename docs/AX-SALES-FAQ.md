# AX Sales FAQ

Cadence 17. Concise answers for live meetings.

## Is this replacing CAMARA?

No. NetAware AX uses Network APIs as the execution layer. AX adds Intent, discovery, governance, and fulfillment above them. AX builds on DX. It does not replace APIs or developers.

## Is NetAware making the business decision?

Only within configured autonomy. Rocket Bank still owns the financial decision. High Flight still owns device reassignment.

## Is this a generic AI agent?

No. This prototype uses deterministic configured behavior. The architecture is governed Intent execution. There is no live MCP, A2A, or LLM planner.

## Does NetAware own operator APIs?

No. Operators expose network capabilities. NetAware discovers and fulfills Intents using available direct or aggregated supply. Aggregators are routed through / normalized through / available via.

## Is this live operator availability?

No. Coverage is configured demo coverage. Simulated operator response. Not a production SLA.

## Why Network APIs?

They add observe / verify / act that the enterprise application does not have itself. They do not replace BRS, DCS, OTA, IAM, or claims systems.

## Why NetAware?

Applications should not have to understand every operator implementation. Operators should see which enterprise Intents their capabilities can fulfill. Aggregators can broaden reach; NetAware normalizes that supply against Intent.

## How does it know what to invoke?

Capability discovery funnel: application / Intent → candidates → configured eligibility → runtime feasibility → fulfillment → call / reuse / skip / filter / unavailable.

The Use Case ↔ API Map shows what could apply. AX determines what should apply now.

## What if supply is missing?

Qualified demand can exist while fulfillment is blocked. Example: Provider B Number Verification API is available, ECS is not ready, Wi-Fi demand is unfulfilled. That is enablement impact, not lost revenue.

## CityCare — is more data better?

No. Age Verification is sufficient. Broader KYC Match is filtered. Minimum appropriate capability. Available does not mean appropriate.

## Acme inspection — why is this AX?

Observe → objective breach → replan → QoD becomes useful → act → verify → ASSURED. The API call is not the outcome. The verified business objective is the outcome. HTTP 201 is not success.

## High Flight — does the network track bags?

No. Network reachability tells the baggage system whether the assigned scanner can complete the digital workflow.

## OTA — does NetAware install firmware?

No. It adds network readiness to the enterprise OTA decision. Provider C roaming gap is a 500-device simulated qualified-demand gap.

## Evidence reuse

Not every Intent causes another network call. Fresh, purpose-compatible evidence can be reused. Secondary story, not the hero.
